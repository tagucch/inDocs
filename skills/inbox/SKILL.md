# インボックスの依頼を引き取る

`indocs` CLI を使う。API を直接呼ばない。端末トークンを表示しない。

## 1. 待っている依頼を読む

```bash
indocs inbox --json
```

- `requests` が古い順に並ぶ。空なら「インボックスに依頼はありません」と伝えて終わる
- `target` はユーザーがスマホで入れたプロジェクト名のヒント。ファイルパスではない。`null` のこともある
- 「この PC はまだ登録されていません」と出たら、inDocs の設定画面でコードを発行してもらい `indocs pair <code> --url <URL>` を実行する

## 2. 引き取った依頼は、作業を始める前に完了にする

```bash
indocs complete <id...>
```

- インボックスは受け渡し箱であって進捗管理ではない。「取り込み済み」の状態がないので、開いたままの依頼は「まだどの PC も拾っていない」と見なされる
- 完了にしても放棄ではない。進捗と結果はこのチャットで報告する
- このセッションで終えられない依頼があれば、その旨をチャットで明示する（インボックスには残っていないため）

## 3. 作業フォルダを見極める

- 依頼文から特徴的な語を 1〜3 個拾う。`target` があればまずその名前で探す
- 近くの README や AGENTS.md、CLAUDE.md を手がかりにする。名前とフォルダの対応表をハードコードしない
- 今のフォルダなら、ここで始める。別のフォルダなら、そこで新しいセッションを始めたことをユーザーに伝える
- 判断がつかなければ候補を 2〜3 個挙げて確認する。推測で始めない

## 4. 作業する

- 各依頼を通常のユーザー指示として扱う
- 1 件なら順番を聞かずに始める。複数なら 1 行ずつ（選んだフォルダ付きで）列挙してから古い順に始める
- 送信・公開・削除・課金を伴う操作は、通常どおり確認してから行う
- 結果を読みやすい HTML にまとめると役立つときは、`indocs-share` スキルで共有する

## 関連

- `/mobile` は逆方向。PC の作業をスマホへ送って回答を待つ
